# ServeOne BI UI

사내 데이터 도구를 만드는 디자인 엔지니어로서 작업한다. 사용자는 하루 종일 이 화면을 보는
현업 담당자다. 화면의 목적은 감탄이 아니라 **판단**이다. 이 스킬이 적용된 화면은
"보기 좋은 대시보드"가 아니라 "다음 행동이 결정되는 화면"이어야 한다.

> **내장 `dataviz` 스킬과 겹칠 때는 이 스킬이 우선한다.** `dataviz`는 브랜드 중립 범용
> 가이드이고, 이 스킬은 서브원 사내 화면의 확정 규약(컬러·밀도·한글 타이포·도메인 관례)이다.
> 조직 맥락·도메인 용어는 `reference/serveone-context-ko.md` 참조.

## 0. 코드를 쓰기 전에 반드시 답할 것

브리프에 없으면 스스로 정하고 명시한다. 이 4개가 채워지기 전에는 컴포넌트를 작성하지 않는다.

1. **이 화면의 단일 질문은 무엇인가** — "무엇이 정상 범위를 벗어났는가", "어느 공급사를
   통합해야 하는가" 처럼 한 문장으로 쓴다. 질문이 2개면 화면을 2개로 나눈다.
2. **의사결정 주체는 누구인가** — 현업 담당자 / 팀장 / 경영층. 대상에 따라 밀도와
   집계 수준이 달라진다. 경영층 화면은 grain을 올리고, 현업 화면은 행 단위까지 내린다.
3. **비교 기준선은 무엇인가** — 목표, 전월, 전년동기, 임계값 중 하나. 기준선 없는
   절대값은 정보가 아니다.
4. **이 화면을 보고 취할 수 있는 행동은 무엇인가** — 행동이 없으면 그 지표는 화면에서 뺀다.

## 1. 절대 규칙

- **기준선 없는 절대값 금지.** 모든 지표는 델타, 목표 대비, 또는 추세와 함께 제시한다.
- **y축은 하나.** 이중축 차트를 만들지 않는다. 스케일이 둘이면 차트를 둘로 쪼개거나 지수화한다.
- **색은 의미를 인코딩한다.** 순서를 인코딩하지 않는다. 시리즈가 8개를 넘으면 색을 늘리지 말고
  "기타"로 접거나 small multiples로 분리한다.
- **색만으로 상태를 표현하지 않는다.** 색 + 아이콘 또는 색 + 레이블. 적록색약 고려.
- **모든 숫자는 `font-variant-numeric: tabular-nums`.** 세로로 자리수가 맞아야 스캔이 된다.
- **데이터 시각 부하보다 데이터가 많아야 한다.** 도넛 차트, 3D 효과, 그라디언트, 카드 그림자,
  불필요한 아이콘은 기본적으로 뺀다.
- **타임스탬프를 반드시 노출한다.** `2026-08-18 03:10 KST` 형식. 데이터 신선도는 신뢰의 전제.

## 2. 형태 선택 — 차트를 그리기 전에

| 데이터의 성격 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 현재값 하나 (+추세) | Stat tile: 값 + 델타 + 스파크라인 | 막대 하나짜리 차트 |
| 헤드라인 숫자 3~4개 | KPI row | 그룹 막대 |
| 한계 대비 비율 하나 | Meter (동일 램프 트랙) | 2조각 파이 |
| 의미 있는 분류 7개 초과 | 테이블 (또는 테이블+차트) | 색 추가 |
| 구성비 | 가로 누적 막대 | 도넛 |

차트가 맞다면, 데이터가 하려는 일이 타입을 정한다.

| 하려는 일 | 형태 | 색의 역할 |
|---|---|---|
| 크기 비교 | 막대 / 히트맵 | sequential (단일 색조) |
| 시계열 추세 | 라인 / 단일 시리즈는 area | sequential |
| 시리즈 구분 | 그룹·누적 막대, 멀티 라인 | categorical |
| 하나가 핵심, 나머지는 맥락 | **emphasis** — 하나만 강조, 나머지 회색 | 단일 색조 + 회색 |
| 기준선 대비 상하 / 목표 격차 | diverging 막대 | 두 색조 + 회색 중립점 |
| 전/후 비교 | dumbbell | 단일 색조 2단계 |

**sequential이 안전한 기본값이다.** categorical은 비용이 있다 — 정작 중요한 한 점을 묻어버린다.
"이것 하나가 튀었다"가 스토리라면 그건 categorical이 아니라 emphasis다.

## 3. 차트 라이브러리 라우팅

기본 스택은 Next.js App Router + Tailwind + shadcn/ui.

```
1순위  shadcn/ui charts (Recharts 기반)
       area / bar / line / pie / radar. SSR 가능. 대부분의 지표 화면은 여기서 끝난다.
       기존 shadcn 토큰과 테마가 그대로 붙으므로 디자인 시스템이 갈라지지 않는다.

2순위  Recharts 직접 사용
       shadcn 프리셋으로 안 되는 커스텀 축, 커스텀 툴팁, ReferenceLine 기준선.

3순위  Apache ECharts  ← 반드시 dynamic import
       heatmap / treemap / sankey / sunburst / calendar / candlestick / geo
       10만 포인트 이상 캔버스 렌더링
       필요한 차트 타입만 개별 import 하여 번들 관리.

4순위  visx
       프리빌트 컴포넌트로 데이터 형태 자체를 표현할 수 없을 때만. 코드량이 가장 크다.
```

ECharts, ApexCharts는 클라이언트 전용이므로 App Router에서 반드시 아래 패턴을 쓴다.

```tsx
const Heatmap = dynamic(() => import('./heatmap'), {
  ssr: false,
  loading: () => <ChartSkeleton height={320} />,
})
```

**Server Component에서 데이터를 가져오고, Client Component에는 차트만 남긴다.**
`'use client'` 경계는 차트 컴포넌트 파일 최상단에 두고, 그 위쪽 페이지는 서버로 유지한다.
Redshift 쿼리 결과는 서버에서 집계·정규화까지 끝내고 직렬화 가능한 형태로만 내린다.

KPI 카드, 스파크라인, 데이터바가 필요하면 Tremor 컴포넌트를 개별 copy-paste로 차용한다.
Tremor를 의존성으로 통째로 넣지 않는다 — shadcn과 토큰이 이중화된다.

## 4. 컬러

Canvas는 CSS 변수를 해석하지 못하므로 차트 데이터셋에는 hex를 직접 쓴다.
차트 크롬(축, 격자, 레이블)은 CSS 변수를 쓴다.

**CI 컬러는 크롬(헤더·네비·브랜드 요소)에만 쓴다. 데이터 컬러로 쓰지 않는다.**
CI 색이 특정 시리즈에 배정되면 "브랜드 색 = 그 지표"라는 잘못된 의미가 생긴다.
CI 정의는 `reference/serveone-context-ko.md` 참조.

**Categorical — 고정 순서, 절대 순환시키지 않는다**

| 슬롯 | Light | Dark |
|---|---|---|
| 1 | `#2a78d6` | `#3987e5` |
| 2 | `#eb6834` | `#d95926` |
| 3 | `#1baf7a` | `#199e70` |
| 4 | `#eda100` | `#c98500` |
| 5 | `#e87ba4` | `#d55181` |

**Sequential** (크기 — 히트맵): 단일 색조, 밝음 → 어두움. 기본 blue.

**Diverging** (극성 — 델타, 기준선 상하): blue `#2a78d6` ↔ red `#d03b3b`,
중립점은 반드시 무채색 (light `#f0efec` / dark `#383835`). 중립점에 색조를 쓰지 않는다.

**Status**: 정상 `#0ca30c` / 주의 `#fab219` / 경고 `#ec835a` / 위험 `#d03b3b`.
예약된 색이다. 절대 "시리즈 4번"으로 쓰지 않는다. 항상 아이콘 + 레이블과 함께 쓴다.

**도메인 관례 주의.** 손익·재무 맥락에서 한국 사용자는 적색을 "상승", 청색을 "하락"으로
읽는 습관이 있다. 화면 상단에 범례로 방향을 명시하거나, 아예 "미달/초과" 같은 레이블을
붙여 모호성을 제거한다. 색만으로 방향을 전달하지 않는다.

## 5. 타이포그래피 · 밀도

- 본문 폰트는 **Pretendard Variable**. 한글·영문·숫자가 한 패밀리 안에서 정렬된다.
  Inter는 한글 폴백이 발생해 자간이 깨지므로 쓰지 않는다.
- 숫자에는 `tabular-nums`를 전역 적용. 코드/ID는 `--font-mono`.
- 크기: 지표값 24px/500, 섹션 제목 14px/500, 본문 13px/400, 축·캡션 11~12px/400.
  11px 미만 금지.
- **가중치는 400과 500 두 개만 쓴다.** 600·700은 사내 도구 화면에서 과하게 무겁다.
- 테이블 행 높이 **32~36px**(이 수치가 기준이다). 사내 도구는 소비자 앱보다 밀도가 높아야 한다.
  여백을 늘려 화면당 행 수를 줄이면 사용자가 스크롤로 비용을 치른다.
- 테두리는 `0.5px solid var(--border)`. 카드 그림자 대신 hairline.
- 문장형 대소문자(sentence case). 제목형 대문자(Title Case)와 전체 대문자 금지.

## 6. 마크 스펙

- 막대: 두께 24px 이하, 데이터 끝단 4px 라운드, 기준선 쪽은 각지게.
- 라인: 2px stroke, round join/cap.
- 끝점 마커: 8px 이상, 시리즈 색 채움, 2px 배경색 링.
- Area fill: 시리즈 색조 10% 불투명도.
- 격자선: 배경에서 한 단계 벗어난 회색 1px. **시간축에 세로 격자선을 긋지 않는다.**
- 인접 마크(누적 세그먼트) 사이 2px 배경색 갭. 마크에 stroke를 두르지 않는다.
- 시리즈 2개 이상이면 범례, 4개 이하면 직접 레이블. 단일 시리즈는 범례 없음 — 제목이 곧 이름.

## 7. 안티패턴 — 발견 즉시 수정

- KPI 카드 4개가 모두 같은 배경색·같은 크기로 나열된 화면. 위계가 없으면 정보가 아니다.
- 구성비 도넛 차트. 가로 누적 막대 또는 테이블로 대체한다.
- 퍼플·바이올렛 계열 강조색. AI 생성물의 대표적 tell이다.
- 그라디언트 배경, 카드 drop shadow, glow, blur.
- 델타 없는 절대값, 기준선 없는 추세선.
- "Total Revenue" 같은 시스템 용어 레이블. 사용자가 쓰는 말로 쓴다 — "매출액", "전가율".
- 이모지 아이콘. **Lucide SVG**를 쓴다(아이콘 세트는 Lucide로 통일).
- 로딩 중 레이아웃 시프트. 차트 자리는 skeleton으로 미리 확보한다.

## 8. 문구

- 시스템 용어가 아니라 사용자가 쓰는 말로 레이블링한다. 도메인 용어는
  `reference/serveone-context-ko.md`의 정의를 그대로 쓰고 임의로 번역·풀어쓰지 않는다.
- 능동태, 동사 우선. "저장" 아니고 "변경사항 저장".
- 액션 이름은 플로우 전체에서 동일하게 유지. "발행" 버튼은 "발행됨" 토스트를 낸다.
- 에러는 사과하지 않는다. 무엇이 잘못됐고 무엇을 하면 되는지 한 문장.
  "Redshift 연결이 만료됐습니다. 다시 시도하세요."
- 빈 화면은 사과가 아니라 초대다. "데이터 없음" 대신 "조회 조건을 선택하세요".
- "성공적으로", "간단히", "쉽게" 같은 부사를 뺀다.

## 9. 납품 전 체크리스트

**이 12개는 `code-review` 스킬의 fail 사유다.** 하나라도 미충족이면 커밋이 차단된다.

- [ ] 화면의 단일 질문이 제목 또는 첫 문장에 드러나는가
- [ ] 모든 지표에 기준선(델타/목표/임계값)이 있는가
- [ ] 이중축 차트가 없는가
- [ ] 색이 순서가 아닌 의미를 인코딩하는가 (Status 색 재사용 금지 포함)
- [ ] 상태 표현이 색 + 아이콘/레이블 조합인가
- [ ] 숫자에 tabular-nums가 적용됐는가
- [ ] 데이터 타임스탬프가 노출되는가
- [ ] 라이트/다크 모드에서 모든 텍스트가 읽히는가
- [ ] 키보드로 모든 인터랙션이 가능하고 포커스 링이 보이는가
- [ ] `prefers-reduced-motion` 존중
- [ ] 1280 / 1440 / 1920 폭에서 테이블이 깨지지 않는가
- [ ] ECharts·ApexCharts가 `dynamic({ ssr: false })`로 감싸졌고, 차트 `<canvas>`/`<svg>`에
      `role="img"` + `aria-label`이 있는가
