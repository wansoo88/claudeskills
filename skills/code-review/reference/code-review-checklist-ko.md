# 코드리뷰 체크리스트 (참조)

## 정확성 (fail 가능)
- [ ] 엣지케이스(빈값·null·경계·대량) 처리
- [ ] 에러 처리·예외 전파가 적절, 조용한 실패 없음
- [ ] 동시성/경쟁조건 이슈 없음
- [ ] 반환값·상태코드가 계약(API spec)과 일치

## 설계/구조
- [ ] 레이어 경계 준수(SQL은 데이터 레이어, 규칙은 도메인)
- [ ] 단일 책임, 과도한 결합/중복 없음
- [ ] 이름이 의도를 드러냄, 매직넘버 없음

## 테스트 (fail 가능: 핵심 로직 테스트 부재)
- [ ] 핵심 로직에 단위테스트 존재
- [ ] 실패 케이스도 테스트, 커버리지 합리적

## 성능
- [ ] N+1 쿼리·불필요한 반복 없음
- [ ] 대량 데이터에 스트리밍/페이지네이션

## 가독성/유지보수
- [ ] 주변 코드 스타일과 일치
- [ ] 주석은 '왜'를 설명(자명한 '무엇'은 지양)

## 보안 냄새 (발견 시 security-review로 강하게 연계)
- [ ] 하드코딩된 비밀정보 없음
- [ ] 사용자입력 검증, SQL 파라미터 바인딩

## UI 게이트 — 화면/차트 변경 시에만 적용 (12항목 **전부 fail 가능**)

> 기준 원문은 `serveone-bi-ui` 스킬. 아래 중 **하나라도 미충족이면 fail**이다.
> 적용 대상: 화면 컴포넌트·차트·데이터 테이블·대시보드 변경 PR. 백엔드/파이프라인 전용 변경은 해당 없음.

- [ ] 화면의 단일 질문이 제목 또는 첫 문장에 드러남
- [ ] 모든 지표에 기준선(델타/목표/임계값)이 있음
- [ ] 이중 y축 차트 없음
- [ ] 색이 순서가 아닌 의미를 인코딩 (Status 예약색을 일반 시리즈로 재사용 금지)
- [ ] 상태 표현이 색 + 아이콘/레이블 조합 (색만으로 표현 금지)
- [ ] 숫자에 `tabular-nums` 적용
- [ ] 데이터 타임스탬프 노출 (`2026-08-18 03:10 KST` 형식)
- [ ] 라이트·다크 모드 양쪽에서 모든 텍스트 판독 가능
- [ ] 키보드로 모든 인터랙션 가능, 포커스 링 표시
- [ ] `prefers-reduced-motion` 존중
- [ ] 1280 / 1440 / 1920 폭에서 테이블 미파손
- [ ] ECharts·ApexCharts가 `dynamic({ ssr: false })`로 감싸짐 + 차트 요소에 `role="img"` + `aria-label`

## 판정 기준
- 정확성 결함 / 보안 냄새 / 핵심 테스트 부재 / 레이어 위반 → **fail**
- **UI 게이트 12항목 중 하나라도 미충족 → fail** (화면/차트 변경 PR에 한함)
- 경미한 개선만 있으면 코멘트 후 **pass**
